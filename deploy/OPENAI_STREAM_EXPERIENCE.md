# OpenAI 全程卡顿调度

此优化默认启用，直接参与 OpenAI 的 `health_first` 和
`health_cost_balanced` 两档选号。没有仅观察阶段，也不需要第二次启用。
其他平台与严格优先级排序不使用此信号。新实例需要先积累可比较样本，
数据不足时沿用原规则。

## 生效条件

按账号、实际请求上游模型、实际上游传输、reasoning effort、请求字节大小档位、
service tier、是否声明工具、是否携带 continuation 分开记录。请求大小采用 16 KiB、64 KiB、
256 KiB、1 MiB 分界；这是发送的请求大小，不是供应商内部完整上下文长度。
缺省 effort/tier 保留为独立的 `unspecified`，不混入显式档位。
模型维度遵循对应转发路径：普通转换路径使用 Composite/渠道解析、账号映射和现有
OAuth 模型规范化；透传路径保留实际发送的 body 模型，不额外套用普通账号映射。
HTTP Responses 使用 SSE 维度，即使账号同时启用了 WS。

每个维度保留最近 10 条观察，至少 5 条新鲜且完整成功的样本才参与比较。
有效期沿用分组的健康数据有效期。失败、取消和不完整观察不能建立健康基线，
仍保留现有错误健康处理。

新增信号要求长间隔的样本中位数同时达到以下条件，而且最近 5 个完整样本中
至少 3 个达到该条件：

- 默认至少 20 秒；
- 比可比较候选至少慢 50%；
- 比可比较候选至少多 5 秒。

“更好的候选”必须在整体窗口和最近 5 次完整样本中都支持改善，不能只凭早期快样本
继续充当顺畅基线。最近也变慢时，不因旧快样本降权其他账号或触发更贵成本层。

比较全程有效进展间隔（包含工具参数阶段）。工具阶段间隔、首次可用文字/工具参数、
长间隔次数和累计等待也作为内容无关的诊断数据记录，不单独凭首次文字慢降权。
工具阶段同一次停顿不会重复计分；排序采用预先计算的等级，避免比较器互相矛盾。

## 两档行为

健康优先保留原有错误健康和 TTFT 判断，在相同原有健康等级中，把持续卡顿的
账号排后，再应用成本、普通粘性和负载规则。慢账号仍为容量兜底。
普通粘性不能把已证明卡顿的账号重新提到顺畅候选之前。
旧版选号路径的负载打散和缓存亲和同样不能跨越卡顿等级，等级内保留原行为。

成本均衡先在原成本层内排序。新增的中途卡顿升层必须满足整层所有账号都有
可信劣化证据，且更高的精确成本层存在对整个基准层均明显更好的已测账号。
更贵但未知或同样慢，不因这个新信号升级。层内仍保留账号作为容量兜底。
原有 TTFT 升层规则和 OAuth/setup-token 主路由及其特殊兜底规则保持独立。

全部同样慢而没有明显改善候选时，新信号不会把账号全部淘汰，也不会因为
普遍卡顿持续升层。这是缺少改善证据，不足以单独认定供应商发生事故。

恢复使用后续正常请求，不额外发送付费探测。最多每 20 次排序评估允许一次
恢复提升，进程整体提升间隔至少 1 分钟，同维度账号提升间隔至少 5 分钟；
提升仍受原有健康和路由限制。最近 5 次中有 3 次恢复正常即可解除重复劣化条件。
过期样本退回未知状态，不能维持永久处罚。

## 转发边界

Go/Rust 的 SSE 和 Responses WebSocket 均采集供应商读取等待。
虚拟计时只推进上游读取/等待事件的时间，排除下游写阻塞、本地处理、队列等待、
两轮之间的用户和工具执行时间。首次可用内容的记录值是正文阶段累计上游等待，
独立于现有请求 TTFT，不能拿它替换首 token 指标。

真实 reasoning、文字和工具参数增量算进展，心跳及本地占位不算。
持续正常 reasoning 不因总思考时间长被直接惩罚。因此，此优化不能可靠识别
所有“持续输出 reasoning 但思考很久”的任务，也不按 token 吞吐量处罚复杂任务。

WebSocket 按轮记录，并区分 continuation。供应商内部完整上下文和任务复杂度
仍然未知，所以这些比较是重复相对证据，不是因果归因。并发重叠生成、超大 SSE
事件或无法可靠确定维度的路径保持中性。图像和 native compaction 不使用新样本。
Go WS 入站只有请求大小档位可能达到动态 HTTP bridge 阈值、账号固定 HTTP bridge
或上游强隔离时，选号阶段保守保持中性，避免把 WS 样本用于实际的 SSE/重放请求。
默认开启动态 bridge 不会停用普通大小的 WS 调度；passthrough 不受动态桥接阈值影响。
原桥接行为照常运行。

`previous_response_id` 的强连续性绑定保留，生成中的请求不因评分变化换号或重放。
优化主要影响后续可选号的请求，不能把当前已经卡住的执行无缝迁移走。

## 配置与回退

```yaml
gateway:
  scheduling:
    stream_experience_enabled: true
    stream_experience_gap_seconds: 20
```

环境变量：`GATEWAY_SCHEDULING_STREAM_EXPERIENCE_ENABLED`、
`GATEWAY_SCHEDULING_STREAM_EXPERIENCE_GAP_SECONDS`。
`gap_seconds: 0` 使用默认 20 秒；显式值范围为 1–600 秒。
将 enabled 设为 false 并按现有部署流程重启 Go，即可停止新采样和新排序。
无需迁移数据库，不修改 TTFT 定义、占位输出、流内容、超时、计费或续链协议。

## 同步与诊断

本地内存最多 4096 个维度，每个维度最多 10 个样本。缓存满载时按访问顺序直接淘汰
最旧维度，避免逐次扫描整张表。选号只读本地快照，
Redis 读写通过有界后台队列完成，单次 I/O 预算 250 ms。队列满或 Redis 不可用
不阻塞请求，本机样本仍可参与判断；跨实例共享会延迟。关闭进程不保证排空
尚未同步的观察队列，这些数据不是计费凭据。

Redis 使用 `sub2api:openai:experience:v1:*` 独立键，键名散列维度、值只含计时和
有界请求分类。完整样本在收到上游终止事件时固定观察时间，下游慢写和延迟回调
不刷新样本年龄。Redis 按观察时间保留最新 10 条，延迟 WAL 回放的旧事件不能
挤掉新观察。共享窗口按事件 ID 去重，不为每次请求新增独立 Redis 收据键。
旧 Rust、旧 Go 回调和旧 WAL 不含此可选字段时继续兼容。
生产启用完整覆盖需要同时更新 Go 和 Rust 二进制。

`SnapshotOpenAIAccountSchedulerMetrics().StreamExperience` 提供 keys、samples、
decisions、common_slow、queue_drops、redis_errors。发生降权选路变化时输出
`openai stream experience deprioritized candidate` 结构化日志，日志全进程最多每分钟
一次，计数器继续累计。多个可比较账号都反复长停顿且没有改善候选时，
记录 `common_slow` 和 `openai stream experience no better candidate`，不自动归因官方故障。重连诊断增加 `failure_class`、`connection_segment`、
transport、lease ID；Go 到 Edge 的请求连接失败单独记录 `go_edge`。

`edge_downstream` 表示 Edge 观察到的下游断开，可能位于 Go–Edge 这一跳，
不能直接认定终端用户取消。排查需要关联 edge request ID 和现有请求日志。
没有经过网关的客户端发送失败无法由账号健康调度识别。
