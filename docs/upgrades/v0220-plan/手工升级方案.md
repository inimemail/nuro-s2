### O03 本地新增：CSV降低峰值内存，导出专用有界分页

**事实：** 当前导出同时保留 `allLogs[] → rows[][] → csvContent string → Blob`，且从当前列表pagination.total预估总页数；后端普通列表使用 `LIMIT/OFFSET`。`usageLogOrderBy`已经有id作为tie-breaker、`escapeCSVValue`已有公式防护，这两项不重复重做。

**分两步落地，均在实施范围：**

1. 1000条一页顺序取数，当页即转换为CSV片段加入Blob parts，释放当页UsageLog和关联对象；不保留allLogs和二维rows，不使用Promise.all并发抓页；保留BOM和所有现有列/格式。Blob最终仍需与文件大小成比例的内存，不能宣传完全常数内存。取消/异常释放片段引用、AbortController、计时器和object URL。对象URL在浏览器完成下载调度后清理，卸载和失败也有兜底。大文件无能力安全处理时在开始/处理中明确提示缩小范围或分段，不能静默截断、默默只导前N条或假报成功。
2. 在当前普通用户 `/usage` 增加**显式导出模式**，普通列表分页响应完全不变。第一批冻结已验证用户、原筛选/时区/排序和当前可见数据的id高水位；后续用小型签名cursor绑定这些条件及last排序值/id，`LIMIT 1001`返回1000和has_more，不按列表total推算结束，不逐页COUNT，也不越翻越深OFFSET。沿现有whitelist排序表达式（id、created_at+id、requested_model实际表达式+id）生成参数化keyset；不能接受cursor里的任意SQL或user_id，更不能用全库max id泄漏其他用户活动。每页仍以当前session owner与现有APIKey归属规则验证，cursor不是新授权凭据；跨用户/换筛选/换时区/换排序/篡改/过期明确拒绝，取消和429安全重试同一cursor，不消耗推进位置。签名复用现有稳定服务器密钥管理，不新建DB session表/Redis导出任务。

这冻结的是新增写入边界，不是跨多次HTTP请求的数据库强一致快照：cleanup若删除历史行，不可能凭空恢复；使用keyset保证不会因OFFSET前移继续漏掉其他尚存行，对删除/到期明确说明，不声称绝对等同导出起点的全部数据。开始时未提交、之后才提交且id较小的记录也受MVCC可见性限制；不能靠长事务跨用户等待HTTP连接解决。若需要法规级固定快照属于独立离线导出，不混入本次。

文件：`UsageView.vue`、`api/usage.ts`、types；`handler/usage_handler.go::List`的独立导出分支、`service/usage_service.go`、repository接口/`usage_log_repo.go`新增导出查询helper与cursor纯函数。`ent/schema/usage_log.go`已有user/time和id相关索引基础，先对脱敏测试数据EXPLAIN ANALYZE，不能凭推测新增索引迁移。查询仅后台主动导出，不影响网关、usage写入、billing/audit和旧查询总数语义。验证插入/删除/同时间同模型、双向排序、深分页、重试/取消、注入/跨用户、1k/10k/大文件堆峰值和SQL次数。

补帧和TTFT必须分别断言：网关注释/占位可以启动下游计时，但不提交upstream；`response.transport_progress.delta`的`delta:"in_progress"`、Chat role-only、结构事件不是real output；不取消后续补帧。OAuth/APIKey独立字段；默认四阶段 `(800/5000)、(3000/10000)、(5000/15000)、(10000/30000)`（阈值/保护上限，ms），最多10。补帧阈值1–100000ms，保护上限为有效正数且不小于同阶段阈值，不设业务最大值；后续阶段两值分别严格递增。OAuth旧标量仍1–3000ms，不能拿旧标量上限限制新阶段；新增阶段两值为空，不能擅自填默认，配置非法明确提示；暂停/恢复降级和关闭完整清理保持。全局阶段只是保存时模板，账号重开复制当前模板、保存后用账号快照，不能恢复runtime global lookup或use_gateway_default marker。

语义学习器保持 `account_id+model+transport+reasoning_effort` 路由，至少8成功样本、最多64样本/4096路由，P95+25%+2s，普通12–30s、高effort20–45s；不足样本/fallback不创建路由，图片排除。reasoning进展只刷新语义计时，不算可见回答；首次可见输出后冻结样本。每请求语义切号最多一次，第二次失败结束，5动作≥3失败暂停10分钟；不清sticky/不记账号失败。该计时与补帧完全独立，WS不下发语义超时字段。

同一逻辑请求切号不重置原coordinator deadline，补帧最多一次；真正输出前才可按现有安全attempt语义切号，真正输出后禁止跨账号拼接。strict_model_priority_on_model_mismatch、倍率探测、抢上游、continuation一次性Redis消费也维持原顺序，不靠新增前置请求“验证能力”。
