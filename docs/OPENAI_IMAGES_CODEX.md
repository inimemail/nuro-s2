# OpenAI Images / Codex 使用说明

适用于本项目的 `/v1/images/generations`、`/v1/images/edits`，以及通过 Responses `image_generation` 工具返回图片的客户端。

## 图片格式与返回内容

`output_format` 表示请求希望得到的编码，不保证所有上游或模型都会返回该编码。`b64_json`、URL 或工具结果中的 base64 描述数据的传输方式，也不能单独证明图片是 PNG、JPEG 或 WebP。

客户端保存图片时应解码并检查实际文件头或使用图片解码器识别格式，再选择扩展名和 MIME。URL 下载应同时检查响应内容；JSON 错误页或 HTML 页面不能当作图片保存。若实际编码不符合本地需求，可以在确认解码成功后在客户端转码。

不要仅因扩展名、MIME 或 `output_format` 不一致就重新生图：原请求可能已完成并产生费用。先检查原响应和已有图片。本项目不会为掩盖格式差异自动重复生成，也不在此次升级中增加图片转码服务。

## Codex 非流式请求的 HTTP 状态

本地非流式 Images 路径没有引入上游新增的 JSON 空白保活，等待最终响应后再提交结果。携带 `X-Codex-Image-Turn-Id` 的请求也沿用该路径，无需依靠该请求头关闭空白保活。这样避免为了保活先提交 HTTP 200，再把迟到错误误认成缺少 `created` 等字段的图片响应。

流式图片响应继续沿用现有 `gateway.image_stream_keepalive_interval` 设置。本次没有新增非流式图片保活配置或按该请求头分流的逻辑；该请求头不会绕过鉴权、分组或图片权限。

## 客户端和代理超时

图片生成可能在首次响应前经历排队、账号选择与上游处理。客户端以及每一层反向代理的响应头和空闲读取超时应覆盖实际图片处理预算；只增大客户端总超时不能解除代理自身的短超时。

例如，若本机部署按 900 秒预算运行图片请求，nginx 的 `proxy_read_timeout` 也需要覆盖该预算和合理调度余量；如前面还有 CDN，需另外核对其限制。请按实际部署设置有限超时，无需为单机引入额外集群组件。

超时不证明上游从未执行。先核对原请求、日志与费用，再决定是否重试。此次说明不改变媒体连接池、图片池、Grok 查询/下载 profile、业务重试或计费规则。
